# 배포 로드맵 — 서브도메인 + 애드센스

작성: 2026-08-30. 이 저장소(rjfo)를 `mddcalc.com` 아래 서브도메인으로 붙여
구글 애드센스로 수익화하기까지의 계획. 유료 판매는 하지 않는다.

---

## 0. 결정 사항

**유료 구독 → 안 함. 무료 + 애드센스로 간다.**

이유는 규제다. 유사투자자문업(자본시장법 제101조)은 ①불특정 다수 대상
②**대가를 받고** ③투자조언, 세 가지가 모두 맞아야 성립한다. 문구만 다듬고
돈을 받으면 여전히 회색지대지만, 무료로 열고 광고로 벌면 ②가 없어서 요건
자체가 깨진다. 애드센스는 규제 우회로가 아니라 정공법이다.

부수 효과로 준비물도 거의 사라진다.

| | 사업자등록 | 통신판매업 신고 | 유사투자자문업 신고 |
|---|---|---|---|
| 유료 구독 | 필수 | 필수 | 필요할 가능성 높음 |
| 무료 + 애드센스 | **불필요** | **불필요** | **해당 없음** |

애드센스는 개인 명의·개인 계좌로 수령하고 종합소득세 때 신고하면 된다.
단 애드센스 수입도 소득으로 잡히므로, 수급자격이나 겸직금지 같은 사정이
있다면 그건 별도로 확인해야 한다.

> 변호사 검토를 받은 정리가 아니다. 규모가 커지면 금융감독원에 직접 문의할 것.

## 1. 붙이는 방식 — `tool.mddcalc.com` 서브도메인

`mddcalc-site`는 정적 HTML + Vercel 서버리스 함수(`api/`)이고 rjfo는
Next.js 14 앱이다. **한 Vercel 프로젝트로 합칠 수 없다.**

그래서 rjfo는 별도 프로젝트로 두고 `tool.mddcalc.com`에 연결한다.
애드센스 승인은 도메인 단위라 서브도메인도 함께 커버된다.

```
mddcalc.com          → mddcalc-site  (정적 HTML, 기존)
tool.mddcalc.com     → rjfo          (Next.js, 신규)
```

양쪽 헤더·푸터에 서로 링크를 넣어 크롤러가 오갈 수 있게 한다.
`mddcalc-site/scripts/site-chrome.js`가 공유 크롬을 굽고 있으므로 거기에
`tool.mddcalc.com` 링크를 추가하고, rjfo 쪽에도 같은 푸터를 만든다.

## 3. 붙이기 전에 rjfo에서 걷어낼 것 (권유성 표현)

작업 로그 1장 8번이 거절 원인으로 **"투자 권유성 표현"**을 지목하고 있다
("매수를 검토하는 전략이 유효합니다", "손절매", "언제 주식을 사야 하는가").
mddcalc-site에서 겨우 지운 것을 rjfo가 다시 들여오면 안 된다.

- [ ] `app/cycle/page.tsx:332` — 플레이스홀더 **"예: 지금 사도 되는 자리야?"**
      → "예: 이 지표는 언제 켜졌어?" 처럼 사실 조회형으로
- [ ] `components/AssistantChat.tsx` — 자유 입력 챗을 제거하거나, 미리 정한
      사실 조회 질문만 고르게 바꾼다. 자유 입력이 남으면 이용자가 "지금 살까"를
      묻고 모델이 답하는 경로가 생긴다
- [ ] `app/api/cycle/route.ts:26` — 시스템 프롬프트에 이미 "매수·매도를 권하지
      마라"가 있다. 유지하되 "특정 시점의 매매 판단에 답하지 말고 과거 통계만
      서술하라"로 강화
- [ ] 면책 문구("과거 패턴이며 투자 판단의 근거가 아닙니다")를 모든 화면 상단에도
      노출. 현재는 하단에만 있다
- [ ] `mddcalc-site/disclaimer.html`과 같은 문구로 통일

**남겨도 되는 것:** "상승장 시작", 초록 화살표, "지금 켜짐" 같은 사실 서술.
이건 과거 데이터의 라벨이지 권유가 아니다.

## 4. 비용 — AI 없이 도는 경로가 필요하다

rjfo는 요청마다 Gemini API를 호출하고 20년치 일봉을 받는다
(`app/api/cycle/route.ts`, `maxDuration = 60`). 애드센스 수익으로는
절대 메울 수 없다.

다행히 **숫자는 전부 TypeScript가 계산하고 LLM은 문장으로 옮기기만 한다.**
`lib/cycle/narrative.ts`가 이미 템플릿 서술을 만들 수 있으므로, AI 해설을
꺼도 앱이 그대로 돈다.

- [ ] `?ai=0` 또는 환경변수로 Gemini 호출을 완전히 끄는 경로 추가
- [ ] 기본값을 AI 꺼짐으로. 해설이 필요하면 사용자가 버튼을 눌러 호출
- [ ] 인기 종목 N개는 결과를 미리 구워서 정적 HTML로 서빙
      (`mddcalc-site`의 `stock/*.html` 생성기와 같은 방식)

## 5. 진짜 병목은 트래픽이다

작업 로그: **트래픽 하루 0~1명.** 애드센스가 승인돼도 이 트래픽이면 월 수익은
몇 백 원이다. 결제냐 광고냐는 문제가 아니라 볼 사람이 없는 게 문제다.

**rjfo를 붙이는 이유는 수익화가 아니라 트래픽이어야 한다.** "23개 상승장
시작점을 지표 30개로 채점한 결과"는 다른 데 없는 콘텐츠고, 종목별 페이지가
자동 생성되면 색인 대상이 크게 늘어난다.

- [ ] 종목별 사이클 리포트를 정적 페이지로 굽는 생성기
      (`mddcalc-site/scripts/`의 종목 리포트 생성기 패턴 재사용)
- [ ] 각 페이지에 고유 원문 1,500자 이상 (작업 로그 기준: 종목 리포트 평균 1,886자)
- [ ] 사이트맵에 추가

## 6. 애드센스 체크리스트 (서브도메인 쪽)

`mddcalc-site`는 이미 갖췄지만 rjfo 쪽은 처음부터 만들어야 한다.

- [ ] `ads.txt` — 루트에 `google.com, pub-5583100002281558, DIRECT, f08c47fec0942fa0`
- [ ] 개인정보처리방침 (제3자 광고 쿠키 · DoubleClick · 맞춤광고 거부 방법 고지)
- [ ] 이용약관 (광고 게재 조항 포함)
- [ ] 면책조항 페이지
- [ ] 소개 / 문의 페이지
- [ ] 모든 내부 링크를 `<a href>`로 (`onclick` 전용 링크는 크롤링 불가 — 1차 거절의 주원인이었다)
- [ ] 광고에 주의를 끄는 문구 금지 ("아래 광고가 표시될 수 있습니다!" 같은 것)
- [ ] `robots.txt`, `sitemap.xml`
